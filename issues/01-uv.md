# [uv] Python and uv

You need: git done (this repo cloned, `learning/README.md` on a branch).

You will: install Python and uv, then run a script whose dependencies are
declared **in the file**. Every later programming assignment uses that same
pattern. You will not create a project virtualenv and `pip install` into it.

## Steps

1. Install **Python 3.10 or newer** if `python3 --version` is missing or older.
   - Windows: [python.org downloads](https://www.python.org/downloads/) or `winget install Python.Python.3.12`
   - macOS: `brew install python` or the python.org installer
   - Linux: your package manager (`sudo apt install python3` on Debian/Ubuntu)
2. Install **uv**: follow [uv installation](https://docs.astral.sh/uv/getting-started/installation/). Then open a new terminal and run `uv --version`.
3. Optional but used by the README shortcuts: install [Task](https://taskfile.dev/installation/). You can always call `uv run path/to/script.py` instead of `task knn`.
4. Open `learning/uv/hello.py`. It already has a [PEP 723](https://peps.python.org/pep-0723/) header:

   ```python
   # /// script
   # requires-python = ">=3.10"
   # dependencies = []
   # ///
   ```

   That header is how uv knows which Python and which packages the file needs.
   Empty `dependencies` means stdlib only.
5. From the repo root run:

   ```bash
   uv run learning/uv/hello.py
   ```

   You should see `hello from uv` and a Python version of 3.10+. uv will
   download a Python if the system one is too old. There is no `venv` for you
   to activate.
6. Write `learning/uv/notes.md` with: `uv --version`, the Python version
   `hello.py` printed, and one sentence in your own words on what the
   `# /// script` block is for.
7. On a branch named `uv/hello`, commit `learning/uv/notes.md` and open a
   pull request:

   ```bash
   git checkout -b uv/hello
   git add learning/uv/notes.md
   git commit -m "docs(uv): record python and uv versions"
   git push -u origin uv/hello
   gh pr create
   ```

## How later assignments use this

- Each `learning/<slug>/…py` file starts with its own `# /// script` block.
- Run it with `uv run learning/pa-knn/kNN.py …` or `task knn`. uv reads **that
  file's** header, not `pyproject.toml`.
- Third-party packages (matplotlib in pa-metrics, optional CuPy in pa-gpu) are added
  to that file's `dependencies` list. Do not `pip install` them globally.
- If script A imports script B, A's header must list every third-party
  package A still calls. uv does not inherit B's dependencies.

## How you reuse code after pa-knn

Do **not** copy `kNN.py` into the next folder. Import the previous
assignment as a module and subclass it:

```python
from load_assignment import import_pa
knn = import_pa('pa-knn')
class ScaledKNN(knn.KNN):
    ...
```

`learning/load_assignment.py` is provided. The pa-scaled and later skeletons already call
it. If you find a bug in leave-one-out, fix it in pa-knn; pa-scaled will pick it up
the next time it runs.

## Stretch goal (optional)

Stretch goals are extra challenge. Skip this if you want. Revert any
experiment so later tickets still see an empty `dependencies` list on
`hello.py`.

**Challenge:** Add a tiny third-party package to `hello.py`'s script header,
`uv run` it so uv installs that package, write what happened in
`learning/uv/stretch.md`, then **put `dependencies` back to `[]`**. Do not
leave a random package in a file later assignments do not use — isolation
matters more than keeping the toy import.

## Acceptance criteria

- `uv run learning/uv/hello.py` prints a 3.10+ version without activating a venv.
- `learning/uv/notes.md` exists and answers the prompts in step 6.
- A pull request includes that file. The branch is `uv/…` and the commit
  subject matches `type(scope): description`.
- Stretch is optional. Skipping it does not block ra-types.
